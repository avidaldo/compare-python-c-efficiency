# Glossary

Each term is followed by where it is introduced: a main-path notebook (`[01]` to `[05]`) or a deep dive (`[deep: …]`).

## Computers and languages

- **Address**: the number that identifies a position (one byte) in memory. [deep: numbers_and_memory]
- **AOT (ahead-of-time) compilation**: translating a whole program to machine code before it runs; classic compilation. [deep: how_programs_run]
- **Assembly**: the human-readable form of machine code, one line per instruction. [deep: how_programs_run]
- **Bit / byte**: a bit is a single 0 or 1; a byte is a group of 8 bits. [deep: numbers_and_memory]
- **Bytecode**: simple instructions for an imaginary machine; CPython compiles Python source to bytecode and then interprets it. [deep: how_programs_run]
- **Compiler**: a program that translates a whole program into machine code before it runs. [01]
- **Core**: one of the independent processing units inside a CPU; each can run its own work. [04]
- **CPU (processor)**: the part of the computer that executes program instructions. [01]
- **CPython**: the standard implementation of Python, written in C. [deep: how_programs_run]
- **Decorator**: a line starting with `@` above a function, which modifies how the function behaves. [deep: compiling_python]
- **Dynamic typing**: types are checked while the program runs, at each operation (Python). [deep: how_programs_run]
- **Executable**: a file of machine code produced by a compiler, which the operating system can run directly. [01]
- **Extension module**: a compiled file that Python imports like a normal module (for example, one produced by Cython). [deep: compiling_python]
- **High-level language**: a language that hides hardware details and offers convenient structures (Python). [01]
- **Interpreter**: a program that reads another program and carries it out step by step while it runs. [01]
- **JIT (just-in-time) compilation**: compiling the most-used parts of a program to machine code while it runs. [01]
- **Library**: a collection of ready-made code that a program can import and use. [02]
- **LLVM**: compiler technology used by Clang, Rust, Julia and Numba to generate machine code. [deep: compiling_python]
- **Low-level language**: a language close to how the hardware works, with explicit types and memory management (C). [01]
- **Machine code**: instructions encoded as numbers, the only form a CPU can execute. [01]
- **Numba / Cython / PyPy**: tools to run Python code at compiled speed: a function JIT compiler, a Python-to-C translator with type declarations, and a JIT-based Python interpreter. [deep: compiling_python]
- **Shared library**: a file of compiled functions that other programs can load and call; NumPy's core is one. [03, 04]
- **Static typing**: types are declared in the code and checked by the compiler before the program runs (C). [deep: how_programs_run]
- **Thread**: one independent sequence of instructions; several threads can run at once, on different CPU cores or on a GPU. [05, deep: inside_blas]
- **Type**: the kind of a value: integer, decimal number, text… [01, deep: how_programs_run]

## Numbers and memory

- **Boxing**: storing a value inside a full object (with a reference count and a type pointer), as Python does with every number. [deep: numbers_and_memory]
- **Cache**: small, fast memory inside the processor that keeps copies of recently used data; levels L1, L2 and L3. [deep: numbers_and_memory]
- **Cache line**: the 64-byte block in which data moves between main memory and the cache. [deep: numbers_and_memory]
- **Cache-set conflicts**: addresses that map to the same few cache slots and keep evicting one another. [deep: loop_order_and_cache]
- **Floating point**: the binary equivalent of scientific notation: sign, significant digits (mantissa) and exponent. [deep: numbers_and_memory]
- **float64 / float32 / float16**: floating-point formats of 64, 32 and 16 bits, keeping about 15, 6 and 3 decimal digits. [deep: numbers_and_memory]
- **bfloat16**: a 16-bit format with float32's range but fewer digits, common in AI training. [deep: gpu_performance]
- **IEEE 754**: the standard that defines floating-point formats. [deep: numbers_and_memory]
- **Pointer**: a memory address that says where something else is stored. [deep: numbers_and_memory]
- **RAM**: the computer's main memory: large, but slow compared with the processor. [deep: numbers_and_memory]
- **Reference count**: the number of variables pointing to a Python object; the object is freed when it reaches zero. [deep: numbers_and_memory]
- **Register**: one of a few dozen tiny storage slots inside a core, where arithmetic actually happens. [deep: numbers_and_memory, how_programs_run]

## Arrays and linear algebra

- **Array**: a grid of numbers, all of the same type; NumPy's central object. [02]
- **Batch**: a group of examples processed together. [02]
- **Dimension (axis)**: one of the directions of an array; `ndim` counts them, `shape` gives the size along each. [02]
- **Dot product**: multiplying two vectors position by position and adding the results; a weighted sum. [02]
- **dtype**: the data type shared by all values of an array. [02]
- **Feature**: a measurable property of an example, such as a house's area. [02]
- **FLOP**: one floating-point operation (a multiplication or an addition); multiplying two $n \times n$ matrices costs $2n^3$. [02]
- **GFLOPS / TFLOPS**: billions / trillions of floating-point operations per second. [03, 05]
- **Matrix**: a table of numbers with rows and columns (2 dimensions). [02]
- **Matrix multiplication**: computing the dot product of every row of one matrix with every column of another. [02]
- **Scalar**: a single number (0 dimensions). [02]
- **Tensor**: a grid of numbers with any number of dimensions; the name PyTorch and TensorFlow use for arrays. [02]
- **Vector**: an ordered list of numbers (1 dimension). [02]
- **Vectorisation**: replacing Python loops with whole-array operations that run in compiled code. [02, 04]

## AI models

- **Activation function**: a simple function applied after a neuron's weighted sum, such as ReLU. [02]
- **Attention**: the Transformer mechanism by which each token measures how relevant the others are and mixes in information from them. [02]
- **Bias**: a constant added to a neuron's weighted sum. [02]
- **CNN (convolutional neural network)**: a network for images that slides small filters over the image. [deep: matmul_in_ai]
- **Deep learning**: machine learning with neural networks of many layers. [02]
- **Embedding**: the vector of numbers that represents a token. [deep: matmul_in_ai]
- **Filter**: a small grid of weights that detects a pattern in an image. [deep: matmul_in_ai]
- **Inference**: using a trained model to produce outputs. [deep: matmul_in_ai]
- **Layer**: a group of neurons receiving the same inputs; for a batch, one matrix multiplication $XW + b$. [02]
- **LLM (large language model)**: a very large Transformer trained on text, such as the models behind ChatGPT or Claude. [02]
- **Mixed precision**: training with 16-bit matrix multiplications while keeping sums and master weights in float32. [deep: gpu_performance]
- **Model**: a function with learned numbers (parameters) that turns inputs into outputs. [02]
- **Neural network / neuron**: a model built from neurons, each computing a weighted sum, plus a bias, plus an activation. [02]
- **Parameters (weights)**: the adjustable numbers of a model, learned during training. [02]
- **ReLU**: the activation that turns negative values into 0 and leaves positive values unchanged. [02]
- **Token**: a piece of text (roughly a word or part of a word) that a language model processes. [02]
- **Training**: adjusting a model's parameters automatically using examples. [02]
- **Transformer**: the neural network design (2017) behind modern language models. [02]

## Performance techniques and libraries

- **BLAS**: a compiled library of vector and matrix operations, tuned by experts for each processor, which NumPy calls for matrix multiplication. [04]
- **Blocking (tiling)**: splitting matrices into blocks that fit in the cache and reusing each block many times. [deep: inside_blas]
- **FMA (fused multiply-add)**: an instruction computing $a \times b + c$ in one step. [deep: inside_blas]
- **Glue language**: a language used to connect and drive fast components written in other languages; Python's role in AI. [04]
- **Median**: the middle value of a sorted list; used for timings because it ignores occasional outliers. [03]
- **Profiler**: a tool that measures how much time a program spends in each operation. [deep: matmul_in_ai]
- **SIMD**: instructions that apply one operation to several numbers at once. [deep: loop_order_and_cache, inside_blas]
- **Warm-up**: an untimed first run, so one-off costs do not distort a measurement. [03]

## GPUs

- **Asynchronous**: a call that returns before the work is finished; GPU work is asynchronous. [05, deep: gpu_performance]
- **Block / grid**: a group of GPU threads that work on one piece of the data / all the blocks of one kernel launch. [05, deep: gpu_performance]
- **CUDA**: NVIDIA's platform for general-purpose GPU programming: an extension of C/C++, a compiler and libraries. [05]
- **cuBLAS / cuDNN**: NVIDIA's GPU libraries for linear algebra and for neural networks. [05, deep: gpu_performance]
- **GPU**: a processor with thousands of simple cores that work in parallel, originally designed for graphics. [05]
- **Host / device**: in CUDA, the CPU side and the GPU side, each with its own memory. [deep: gpu_performance]
- **Kernel**: a function that runs on the GPU, executed by many threads at once. [05]
- **Latency / throughput**: the time to finish one task / the amount of work finished per second. [deep: gpu_performance]
- **PCIe bus**: the connection between the computer's memory and the GPU. [deep: gpu_performance]
- **Streaming multiprocessor (SM)**: a group of GPU cores that work together. [deep: gpu_performance]
- **Synchronise**: wait until the GPU has finished its queued work. [05]
- **Tensor core**: a GPU circuit specialised in multiplying small matrices. [05]
- **TF32**: a reduced-precision mode that lets tensor cores process float32 data. [deep: gpu_performance]
- **TPU**: Google's chip designed for matrix multiplication. [deep: language_landscape]
- **Triton**: a Python-embedded language for writing GPU code at the level of blocks. [deep: gpu_performance]
- **Warp**: a group of 32 GPU threads that execute the same instruction at the same time. [deep: gpu_performance]
